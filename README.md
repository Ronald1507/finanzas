# Sistema de Finanzas Personales

A full-stack personal finance management system built with **Laravel 13** and **React 19 + Vite**. Tracks accounts, income/expenses, pending transactions, fixed expenses, and monthly closings — all through a clean REST API consumed by a modern SPA.

## Tech Stack

| Layer | Technology |
|---|---|
| Backend | PHP 8.4, Laravel 13, Pest |
| Frontend | React 19, Vite 8, MUI v9, Zustand, React Router v7 |
| Database | SQLite (development) / MySQL 8 (production) |
| Infra | Docker, Docker Compose |

## Features

- **Account Management** — create, edit, and deactivate bank accounts; set the opening balance per month
- **Movements** — record income and expenses by account, month, and category; transfer between your own accounts
- **Pending Transactions** — track payables and receivables; convert them into real movements when settled
- **Fixed Expenses** — manage recurring bills; register and undo payments per month
- **Monthly Dashboard** — current balance, potential balance, and final balance per account and consolidated
- **Monthly Closing** — atomic close that carries final balances forward as opening balances and rolls over unresolved pending items

### Balance formulas

```
current   = opening + income − expenses
potential = current + pending_receivable − pending_payable
final     = current (frozen at closing)
```

Pending items affect only the potential balance. A closed month is immutable — only the most recent closed month can be reopened, and only when the next month is still untouched.

## Quick Start — Docker (recommended)

The only requirement is [Docker Desktop](https://www.docker.com/products/docker-desktop/).

```bash
git clone <repo-url>
cd Sistema_Finanzas
docker compose up
```

That's it. Docker handles dependencies, migrations, and the SQLite database automatically.

| Service | URL |
|---|---|
| Frontend | http://localhost:5173 |
| Backend API | http://localhost:8000/api |

To stop: `docker compose down`

## Local Setup (without Docker)

**Requirements:** PHP 8.4, Composer, Node.js 20, npm

### Backend

```bash
cd backend

# Install dependencies and bootstrap the project
cp .env.example .env
composer install
php artisan key:generate
touch database/database.sqlite
php artisan migrate

# Start the dev server
php artisan serve
```

### Frontend

```bash
cd frontend

# Create the env file pointing at the backend
echo "VITE_API_URL=http://localhost:8000" > .env

npm install
npm run dev
```

| Variable | Default | Description |
|---|---|---|

| `CORS_ALLOWED_ORIGINS` | `http://localhost:5173` | Frontend origin |

| Variable | Default | Description |
|---|---|---|

## Production Deployment

Uses MySQL and nginx to serve the compiled SPA.

```bash
# Required environment variables
export APP_KEY="base64:..."        # php artisan key:generate output
export DB_PASSWORD="..."
export DB_ROOT_PASSWORD="..."
export VITE_API_URL="https://api.yourdomain.com"
export BACKEND_URL="https://api.yourdomain.com"
export FRONTEND_URL="https://yourdomain.com"

docker compose -f docker-compose.prod.yml up -d
```

| Service | Port |
|---|---|
| Frontend (nginx) | 80 |
| Backend API | 8000 |

## API Reference

All endpoints are prefixed with `/api`.

### Accounts — `/cuentas`

| Method | Path | Action |
|---|---|---|
| `GET` | `/cuentas` | List all accounts |
| `GET` | `/cuentas/{id}` | Get one account |
| `POST` | `/cuentas` | Create account |
| `PUT` | `/cuentas/{id}` | Update account |
| `PUT` | `/cuentas/{id}/saldo-inicial` | Set opening balance for the month |
| `POST` | `/cuentas/{id}/desactivar` | Deactivate account |

### Movements — `/movimientos`

| Method | Path | Action |
|---|---|---|
| `GET` | `/movimientos` | List movements (filterable by account/month) |
| `POST` | `/movimientos` | Record income or expense |
| `PUT` | `/movimientos/{id}` | Update movement |
| `DELETE` | `/movimientos/{id}` | Delete movement |
| `POST` | `/movimientos/transferencia` | Transfer between accounts |

### Pending Transactions — `/pendientes`

| Method | Path | Action |
|---|---|---|
| `GET` | `/pendientes` | List pending items |
| `POST` | `/pendientes` | Create pending item |
| `PUT` | `/pendientes/{id}` | Update pending item |
| `POST` | `/pendientes/{id}/concretar` | Settle — converts to a real movement |
| `POST` | `/pendientes/{id}/anular` | Cancel |

### Fixed Expenses — `/gastos-fijos`

| Method | Path | Action |
|---|---|---|
| `GET` | `/gastos-fijos` | List all fixed expenses |
| `GET` | `/gastos-fijos/mes/{mesId}` | List by month (with payment status) |
| `POST` | `/gastos-fijos` | Create fixed expense |
| `PUT` | `/gastos-fijos/{id}` | Update fixed expense |
| `POST` | `/gastos-fijos/{id}/desactivar` | Deactivate |
| `POST` | `/gastos-fijos/{id}/pagar` | Register payment for a month |
| `DELETE` | `/gastos-fijos/{id}/pago/{mesId}` | Undo payment |

### Dashboard — `/dashboard`

| Method | Path | Action |
|---|---|---|
| `GET` | `/dashboard` | Current + potential + final balances per account and consolidated |

### Monthly Closing — `/meses`

| Method | Path | Action |
|---|---|---|
| `GET` | `/meses` | List all months |
| `POST` | `/meses/{id}/cerrar` | Close month (atomic) |
| `POST` | `/meses/{id}/reabrir` | Reopen last closed month |

## Architecture

The backend follows a **Controller → Service → Repository** pattern. Controllers handle HTTP concerns, Services contain business logic, and Eloquent Models serve as the data layer.

The frontend is organized by **feature module** (`features/`), each with its own services, hooks, and components. Shared infrastructure (HTTP client, layout, common components) lives in `shared/`.

```
HTTP Request
    └── Controller (validation, response)
        └── Service (business rules, balance formulas)
            └── Model / Eloquent (persistence)
```
